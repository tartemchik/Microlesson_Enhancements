Self-Assessment Question Type
Requirements & Roadmap
Flexible, non-graded reflection questions with per-choice feedback · Professional skills & AI literacy modules
Enhancement E2 Medium Priority 3-Phase Roadmap 4 User Stories
Context
The Problem & Opportunity
Current State
  • Every question requires a right/wrong binary outcome
  • Learners who pick the "wrong" self-reflective answer feel penalized
  • Reflection and metacognitive moments can't be designed without workarounds
  • Engagement data shows pressure-to-pass reduces honest self-assessment
Desired State
  • A question type where all answers are valid and lead to useful feedback
  • Learners reflect honestly without fear of failing
  • Instructional designers can build metacognitive moments in professional skills content
  • Platform collects learner insight data without score pressure
The Gap
The current assessment system forces every question into a right/wrong paradigm, which blocks the creation of reflective, metacognitive moments that are crucial for professional skills and AI literacy content. This limits learner engagement and the ability to personalize learning paths.
Strategic Value
Enables differentiation in professional skills and test prep · Improves engagement through personalization · Generates learner insight data without "failing" pressure · Positions the platform as supporting holistic learning, not just knowledge checks

Phase 1
MVP Requirements — User Stories
Phase 1 Scope
Self-assessment question type with inline per-choice feedback. No branching, no scoring, no multi-select. Prove the value before adding complexity.
1
Create Self-Assessment Questions
As an instructional designer, I want to create question items where all answer choices are valid and provide unique feedback, so that learners can reflect on their personal situation without fear of being "wrong."
Acceptance Criteria
  • Question type selector includes new "Self-Assessment" option
  • Can add 2–6 answer choices (no minimum of 4 required)
  • Each answer choice has a feedback field (rich text, 500 char max recommended)
  • No "correct answer" designation required or available for this question type
  • Can add question stem/prompt (supports bold, italics, lists)
  • Can preview how question will appear to learners before publishing
  • Question saves with all choices and feedback preserved
Technical note: Build on existing question framework but remove correctness validation. May need new question_type flag in database. Feedback should support same formatting as explanation fields in current questions.
2
Display Inline Feedback on Selection
As a learner, I want to see immediate, personalized feedback when I select my answer, so that I can understand the implications of my choice and feel validated in my self-assessment.
Acceptance Criteria
  • When learner selects an option, feedback appears immediately below the question — no page reload
  • Feedback styling is visually distinct from correct/incorrect styling (neutral purple/lavender, not green/red)
  • Learner can change their selection and see different feedback for the new choice
  • No score or correctness indicator appears at any point
  • Feedback remains visible as learner continues through content
  • Mobile-responsive display at all viewport sizes
Design Constraints
  • Do not use green or red — these signal right/wrong
  • Use purple/lavender palette for feedback container (see mockup above)
  • Use lightbulb icon ("Insight") instead of check/✗
  • Include footer line: "This is a reflection question — there are no wrong answers."
3
Track Learner Selections for Insights
As a content strategist, I want to see aggregated data on which self-assessment options learners choose, so that I can understand learner needs, refine content, and identify patterns across user groups.
Acceptance Criteria
  • System captures which option each learner selected
  • Data associates with user segment (library / military / test prep)
  • Reporting dashboard shows distribution of selections per question
  • Can filter by date range, user segment, and content module
  • Data exports to CSV for deeper analysis
  • Respects existing privacy and anonymization policies
Open Questions
  • Do you track if learners change their answer, or only the final selection?
  • How should the system handle learners who view the question but don't select (skip)?
4
Content Author Flexibility
As an instructional designer, I want to edit self-assessment questions after publication, so that I can refine feedback based on learner data without creating new content versions.
Acceptance Criteria
  • Can edit question stem and feedback text after publication
  • Changes do not invalidate existing learner response data
  • Version history is tracked for audit purposes
  • Warning displayed if question is currently in active use when edits are made
Future consideration: A/B testing different feedback approaches per choice. Not in scope for Phase 1.

Roadmap
3-Phase Development Plan
1
MVP — Self-Assessment with Inline Feedback
Prove the value before adding complexity
New "Self-Assessment" question type in authoring system — no correct answer designation
2–6 answer choices, each with individual feedback field (rich text, 500 char max)
Inline feedback display on selection — purple/lavender palette, lightbulb icon, no score
Learner can change selection and see updated feedback
Basic analytics: capture selection per learner, distribution reporting per question
Post-publication editing without data invalidation
2
Branching & Personalized Next Steps
Use selection data to shape the learning path
Route learners to different content sections or supplemental resources based on their selection
Multi-select option: allow learners to choose more than one answer with combined or per-choice feedback
Enhanced analytics: track answer changes, skip rates, and cross-question patterns
"Progress check" questions that reference earlier selections within the same lesson
3
Extended Reflection Formats
Expand beyond single-choice to richer reflection types
Rating scale questions (1–5 slider) with feedback ranges: "If mostly high…", "If mixed…", "If mostly low…"
Multi-question connected assessments — "Mostly As / Bs / Cs" bucket feedback across a set
Weighted scoring variant for soft-skill self-assessment (e.g., leadership style profiling)
Open-ended text reflection with AI-generated feedback (exploratory — requires AI integration layer)

Spec
Design & Content Specification — Phase 1
ElementSpec
Question type label"Self-Assessment" in authoring system. Displayed to learners as "Reflect" label above stem.
StemRich text. Supports bold, italic, lists. Max 300 characters recommended.
Answer choices2–6 choices. No minimum of 4. No correct answer field. Each choice has its own feedback field.
Feedback per choiceRich text. 500 char max recommended. Appears inline below the question on selection.
Feedback paletteBackground: #EDE8F5 (purple light). Border-left: #7B5EA7 (purple) 3px. No green, no red.
Feedback iconLightbulb SVG. Label: "Insight." Not "Correct" or "Incorrect."
Score displayNone. No score badge, no points value, no correct/incorrect label at any point.
Completion trackingCounted as "attempted" once learner selects at least one choice. Does not affect pass/fail status.
Answer changeLearner can change selection. Feedback updates to reflect new choice. No limit on changes.
Footer line"This is a reflection question — there are no wrong answers." Italic, slate, 11px.
Storyboard notation[Self-Assessment Question] tag. No asterisk (*) on any choice. Each choice followed by Feedback: [text] on next line.
AccessibilityRadio group with role="radiogroup". Each option: role="radio", aria-checked. Feedback panel: aria-live="polite". Footer note: included in ARIA description of question.
